# TestBase 2
_A generalised Translation database for vidicom applications._

## Basics

A **Locale** represents a language, or language variant.\
_A Locale can have a parent, to enable fallback. For example, "en-GB" and "en-US" noth have "en" as parent. If a translation is identical for most/all variants of "en", it can be entered with that Locale, and all variants of "en" that do not have their own distinct translation will inherit from that. An example where variants might differ would be "Catalogue" for "en-GB" vs. "Catalog" for "en-US"._

A **Text Resourcse** represents a text that can be translation.

A **Formality** is a text variant based on formal addressing.\
_An example for that would be the distinction between "Du" and "Sie" in German._

A **Presentation** is a text variant based on circumstances.\
_An example for that would be capitalised vs. lowercase in English, when used in a header vs. normal text, like "Edit Client Application" vs. "Edit client application"._

A **Translation** is a localised value for a **Text Resource** and **Locale**, with optional **Formality** and/or **Presentation**.

A **Client Application** is an application using TextBase 2.

A **Principal** is a user, authenticated using vidicom's Azure AD B2C Tenant.

*1 Table `flat.Translation` is a table generated by database triggers.\
Whenever a relevant record is added, modified, or deleted, this table is rebuilt.\
It holds all Translations for all available Locales, including a fallback routine.\
_Example: A TextResource Translation only exists for "de". You ask for a Translation with "de-AT". `flat.Translation` will have such a direct entry. You do not have to implement the fallback yourself._

## Definitions
1. **"Connected Application"**
	a. TextResource context: connected through table `ClientApplicationTextResource`
	b. Translation context: connected through tables `ClientApplicationTextResource` and `ClientApplicationLocale`
2. **Active Application**: A ClientApplication with `IsActive = true`
3. **Restricted Principal**: A user that is connected to either certain Applications, and/or certain Locales
4. **Unrestricted Principal**: A user that is not connected to any Applications or Locales
5. **"Missing Translation"**: A Translation that is connected to at least one active Application, but falls back to the "undefined" Locale
6. **Terminology**
	a. **Application**: a `ClientApplication` entity
	b. **Locale**: a `Locale` entity
	c. **Text**: a `TextResource` entity
	d. **Translation**: a `Translation` entity
	e. **Flat Translation**: a `flat.Translation` entity

## Principal Roles

1. **SysAdmin**
	- Full administrative access, but still subject to data-integrity rules below
	- Can CRUD Applications, Texts, Formalities, Presentations, Translations
	- Can assign roles and Application/Locale restrictions to users
	- Is always unrestricted
1. **AppAdmin**
	- Can manage one or more assigned Applications
	- Can CRUD `ClientApplicationLocale` and `ClientApplicationTextResource` entries for assigned Applications
	- Ignores Locale restrictions for Application administration purposes
1. **Translator**
	- Can CRUD Texts and Translations within the permitted Application/Locale scope
	- Can be restricted to certain Applications and/or Locales
	- If restricted only by Application, can access all Texts connected to the permitted Application(s)
	- If restricted only by Locale, can access all Texts connected to Applications using the permitted Locale(s)
	- If restricted by both, can access only Texts connected to a permitted Application that also uses a permitted Locale
1. **Consumer**
	- Can only read Flat Translations within the permitted Application/Locale scope
	- Can be restricted to certain Applications and/or Locales

a. Roles can be combined; in particular, a user can be both an AppAdmin, and a Translator
a. A Restricted Principal can only access data for their connected Applications and/or Locales; if restricted by both Applications and Locales, access is limited to the intersection of both restrictions
a. An Unrestricted Principal has access to all Applications and Locales permitted by their assigned role(s)
a. A Text or Translation can only be deleted if it is not connected to any Active Application
a. A Translation can only be modified if it is connected to no more than one Active Application
a. Locales can never be created, modified or deleted by any user; they represent a fixed set
a. An Application can only be deleted if there are no connected Translations
	- According to the Connected Application definition
	- Connected entries are deleted together with the Application
a. Locales, Formalities, and Presentations are readable by every user

When a Principal successfully authenticates with the app, but it not yet stored in the `auth.Principal` table, the user has to enter a reason why they want/need access to TextBase 2.\
The Principal is then added to the database, with Status "Pending" and no Roles.\
This pending state and the given reason are shown to users with the **SysAdmin** role, and they can accept or deny that request.
